# 자동화 회계 ERP (WellBuddyAI) — 조사 결과 및 개발계획

## Context
- **요청**: 이카운트·경리나라·자비스·SAP S/4HANA 같은 회계 프로그램이면서 **자동화**가 핵심인 회계 ERP를 새로 만든다.
- **현재 저장소**: `WellBuddyAI`에는 `README.md` 한 줄만 있다. 처음부터 새로 개발하며, 재사용할 기존 코드는 없다.
- **확정된 결정사항 (사용자 답변)**
  - 대상 고객: 10~50인 규모 **중소기업의 경리 담당자** (웹 SaaS, 한 회사가 한 테넌트)
  - 기능 범위: **이카운트 ERP의 기본 기능 전체**(회계·영업·구매·재고·생산·인사·급여·그룹웨어·모바일)를 기준선으로 삼는다. 여기에 요청 기능인 **자동분개, 증빙 자동수집, 전자결재(상위자 결재), 사원관리, 급여관리, 위치 기반 자동출근(모바일 앱)**을 더한다. 대응표는 3장에 있다.
  - 외부 연동: 파일 업로드, Mock(샌드박스), 실연동(CODEF·팝빌 등) **세 방식을 모두 구현**하고, 회사별 **설정 화면의 스위치로 켜고 끈다**
  - 기술 스택: **TypeScript 풀스택 웹 SaaS**

### 1.3 반드시 반영할 법규·세무 규칙 (2026 기준)
- **부가가치세**: 일반과세자는 연 2회(1기 확정신고 기한 2026-07-27), 간이과세자는 연 1회. 개인사업자는 직전 연도 공급가액 8천만 원 이상이면 전자세금계산서 발급 의무. 매입세액 불공제 항목(기업업무추진비, 비영업용 소형승용차, 면세사업 관련 매입)을 분류한다.
- **계정과목**: 일반기업회계기준 표준 3자리 코드를 시드로 넣는다(101 현금, 103 보통예금, 108 외상매출금, 135 부가세대급금, 251 외상매입금, 255 부가세예수금, 401 상품매출, 451 상품매출원가, 801 급여, 811 복리후생비, 813 기업업무추진비(옛 접대비) 등). 회사가 추가·수정할 수 있다.
- **4대보험 (2026)**: 국민연금 9.5%(근로자·사업주 각 4.75%, 매년 0.5%p씩 인상), 건강보험 7.19%(각 3.595%), 장기요양보험 = 건강보험료 × 13.14%, 고용보험 근로자 0.9%·사업주 1.15~1.65%, 산재보험은 사업주가 전액 부담(업종별 요율). 국민연금 기준소득월액 상한 637만 원·하한 40만 원이며 매년 7월 조정된다. → **모든 요율은 시행일이 붙은 테이블로 관리**한다.
- **소득세**: 근로소득 간이세액표를 데이터로 적재해 조회하고, 지방소득세는 10%. 식대는 월 20만 원까지 비과세.
- **근로기준법**: 임금명세서 교부 의무, 근로시간 기록, 연장·야간·휴일 가산(5인 이상 1.5배).
- **개인정보보호법**: 주민등록번호 암호화 저장 의무, 접근기록 보관.
- **위치정보법**: 위치정보 수집 동의가 필요하다. SaaS로 제공하려면 방통위에 위치기반서비스사업 신고가 필요하다. 위치는 출퇴근 이벤트 시점에만 기록하고 상시 추적하지 않는다.
- **장부 보관 5년 (국세기본법)**: 전기(Posted)된 전표는 수정·삭제할 수 없고 역분개로만 정정한다. 모든 변경은 감사로그에 남긴다.
- **이체(송금) 기능은 1차 범위에서 제외**한다. 전자금융거래법과 은행 펌뱅킹 계약이 필요하기 때문이다.

## 2. 아키텍처

### 2.1 기술 스택
- **Web**: Next.js 15 (App Router) + React + TypeScript + Tailwind + shadcn/ui + TanStack Query + react-hook-form/zod. 전표입력 그리드는 AG Grid Community, 차트는 Recharts.
- **API**: NestJS 11 + Prisma + PostgreSQL 16. OpenAPI(Swagger)에서 타입 클라이언트를 생성해 웹과 앱이 공유한다.
- **비동기 작업**: Redis 7 + BullMQ (수집 스케줄, 자동분개, OCR, 급여 일괄 계산, 알림)
- **모바일 앱**: Expo (React Native, expo-router). 출퇴근 지오펜스, 영수증 촬영, 결재 승인, 급여명세서 조회, 푸시 알림을 담당한다.
- **파일 저장**: S3 호환 스토리지 (로컬은 MinIO). 메일 테스트는 Mailpit.
- **모노레포**: pnpm workspaces + Turborepo. 테스트는 Vitest, 웹 E2E는 Playwright(사전 설치된 Chromium 사용).

### 2.2 디렉터리 구조
```
apps/web            Next.js 웹 (경리/관리자/사원 화면)
apps/api            NestJS API + worker 엔트리(worker.ts, BullMQ 소비자)
apps/mobile         Expo 앱 (출퇴근, 영수증, 결재, 명세서)
packages/db         Prisma schema, 마이그레이션, 시드(계정과목·요율·간이세액표)
packages/shared     zod 스키마, 공용 타입·enum·상수
packages/accounting-core  순수 도메인 로직: 복식부기 검증, 부가세 분리, 4대보험·소득세·수당 계산, 재고 이동평균
packages/integrations     Provider 인터페이스 + 구현체(file, mock, codef, popbill, ocr-*, ai-claude)
infra/docker-compose.yml  postgres, redis, minio, mailpit
docs/               research.md(조사 자료), development-plan.md(본 계획)
```

### 2.3 핵심 설계 원칙
1. **단일 분개장 (Universal Journal)**: 매출·매입·급여·증빙·결재가 모두 `journal_entry`(헤더)와 `journal_line`(라인) 한 곳에 기록한다. 라인에는 계정, 차변/대변, 거래처, 부서, 프로젝트, 부가세코드, 증빙 링크, `source_type`/`source_id`(원천 추적)를 둔다.
2. **금액 정확성**: 원화는 `BIGINT`(원 단위), 외화는 `NUMERIC(18,2)`로 저장한다. 계산은 decimal.js로 하고 float는 쓰지 않는다. 차변 합계와 대변 합계가 같아야 하며, 이를 서비스 계층과 DB constraint trigger 양쪽에서 검증한다.
3. **전표 상태머신**: `draft → pending_approval → posted → reversed`. 마감된 기간에는 기록할 수 없다(`period.locked`).
4. **멀티테넌시**: 모든 테이블에 `company_id`를 두고 PostgreSQL RLS를 적용한다. 한 사용자가 여러 회사에 소속될 수 있다(세무사 확장 대비).
5. **Provider(어댑터) 패턴 + 설정 스위치**
   ```ts
   interface BankProvider      { testConnection(); listAccounts(); fetchTransactions(acct, from, to) }
   interface CardProvider      { fetchApprovals(card, from, to) }
   interface HometaxProvider   { fetchTaxInvoices(dir, from, to); fetchCashReceipts(); fetchCardPurchases() }
   interface TaxInvoiceIssuer  { issue(inv); cancel(id); getStatus(id) }
   interface OcrProvider       { extractReceipt(file): ReceiptFields }
   interface AiClassifier      { suggest(tx, ctx): { account, vatCode, deductible, confidence, reason } }
   ```
   - `integration_setting(company_id, channel, provider, enabled, credentials_enc, schedule_cron)` 테이블을 둔다. channel은 bank/card/hometax/taxinvoice_issue/ocr/ai, provider는 `off | file | mock | codef | popbill | claude | upstage | clova`이다.
   - `ProviderRegistry`가 회사 설정에 따라 구현체를 고른다. 파일 업로드는 항상 켤 수 있고, Mock은 개발과 데모용, 실연동은 API 키를 입력한 뒤 [연결 테스트]를 통과해야 켜진다.
   - **설정 > 연동관리 화면**: 채널별 카드에 ON/OFF 스위치, 공급자 선택, 인증정보 입력, 연결 테스트, 수집 주기, 마지막 수집 결과를 표시한다.
6. **보안**: argon2 비밀번호 해시, JWT 액세스 토큰 + 리프레시 토큰 로테이션, RBAC(관리자/경리/결재자/일반사원). 주민번호·계좌·API 자격증명은 AES-256-GCM으로 필드 암호화하고 키는 환경변수/KMS에 둔다. 금융 데이터 변경은 모두 `audit_log`에 기록하고, 레이트리밋을 건다.

### 2.4 자동화 엔진 (핵심 차별점)
```
[수집] 스케줄(BullMQ) / 파일 업로드 / 앱 영수증 촬영
   → [정규화·중복제거] 해시 기반 dedupe, 공통 RawTransaction 포맷으로 변환
   → [매칭] 카드승인 ↔ 홈택스 카드매입 ↔ 영수증 OCR, 세금계산서 ↔ 통장 입출금(채권·채무 반제)
   → [분류 파이프라인]
        ① 회사 규칙 (거래처·적요 키워드·금액 조건 → 계정/부가세/부서)
        ② 학습 이력 (같은 거래처·적요에서 가장 최근·가장 자주 쓴 계정)
        ③ AI (Claude: 계정과목표 + 거래처 이력 + 부가세 규칙을 컨텍스트로 구조화 출력)
   → [신뢰도 판정] 임계값 이상이면 자동 전기, 미만이면 '자동분개 검토함'으로 보낸다
   → [피드백] 사용자가 수정하면 규칙을 제안하거나 자동 생성해 다음부터 ①에서 처리한다
```
- **추가 자동화**: 통장 잔액과 장부 잔액 자동 대사, 외상매출금 입금 자동매칭, 결재 완료 후 후속 처리(지출결의 → 전표, 휴가 → 근태, 구매요청 → 발주), 월말 급여 자동계산, 부가세 신고 예정 알림, 월마감 체크리스트, 금액 기준 결재선 자동 지정(전결 규정).

## 3. 기능 범위 = 이카운트 ERP 기본 기능 + 요청 추가 기능

기준선은 **이카운트 ERP의 기본 제공 모듈**(회계·영업·구매·재고·생산·인사·급여·그룹웨어·모바일·엑셀 일괄등록·Open API·화면/양식 커스터마이징)이다. 여기에 사용자가 요청한 기능과 자동화를 더한다.
- ★ 표시: 사용자가 요청한 추가 기능 또는 이카운트보다 강화한 자동화
- 이카운트에서도 **유료 부가서비스**인 웹메일·사내메신저는 1차에서 제외한다. 대신 이메일·푸시·(추후) 카카오 알림톡으로 알림을 보낸다.

| 모듈 | 이카운트 기본 기능 (반드시 구현) | ★ 요청 추가·자동화 강화 | 단계 |
|---|---|---|---|

## 6. 검증 방법
- **단위테스트 (Vitest, `packages/accounting-core`)**: 대차 균형 검증, 부가세 공급가액/세액 분리(원 단위 절사), 불공제 처리, 4대보험·간이세액 계산, 재고 이동평균, 지오펜스 거리 계산
- **API 통합테스트**: docker-compose의 실제 PostgreSQL에서 전표 상태머신, 기간 마감 차단, RLS 테넌트 격리(타사 데이터 접근 불가), 전기된 전표 수정 차단
- **E2E (Playwright + Chromium)**: 회원가입 → 회사 생성 → 은행 CSV 업로드 → 자동분개 검토함 확인·승인 → 전기 → 시산표 대차 일치 → 재무제표 확인. Mock 공급자로 외부 계약 없이 전 과정을 재현한다
- **연동 테스트**: CODEF 샌드박스와 팝빌 테스트 환경에 대해 [연결 테스트] 버튼 동작 확인(키가 준비된 뒤)
- 매 단계 `pnpm lint && pnpm typecheck && pnpm test && pnpm build`가 통과해야 커밋한다
