# WellBuddy ERP 테스트 안내 (P0~P2)

지금까지 만든 기능을 내 PC에서 직접 써 보는 방법이다. **Docker Desktop만 있으면 된다.** Node·PostgreSQL을 따로 설치하지 않아도 된다.

테스트할 수 있는 범위:
- **P0 기반**: 가입·회사, 사용자·권한, 설정
- **P1 회계**: 전표, 장부, 재무제표
- **P1b 회계 확장**: 고정자산, 외화, 어음, 예산, 자금
- **P2 증빙·자동분개**: 통장·카드·홈택스 수집, 영수증, 자동분개
- **P3 영업·구매·재고(개발 중)**: 품목·창고·거래처별 단가, 구매 흐름, 판매 흐름, 재고·매출원가

생산(P4) 이후 메뉴는 아직 "준비 중"이다.

---

## 1. 준비

1. **Docker Desktop**을 설치한다(Windows·Mac 모두 가능): https://www.docker.com/products/docker-desktop/
   - **Windows**
     1. 관리자 권한 PowerShell에서 `wsl --install`을 실행하고 PC를 다시 시작한다. 이미 설치되어 있으면 건너뛴다.
     2. Docker Desktop을 설치한다. "Use WSL 2 instead of Hyper-V"는 체크된 그대로 둔다.
     3. Docker Desktop을 실행하고 왼쪽 아래에 **Engine running**이 보일 때까지 기다린다. 로그인은 건너뛰어도 된다.
     4. **새 PowerShell 창**을 열어 `docker --version`이 나오는지 확인한다. 설치 전에 열어 둔 창에서는 `docker`를 찾지 못한다.
     - "가상화를 켜야 한다"는 메시지가 나오면 BIOS에서 가상화(Intel VT-x 또는 AMD-V)를 켠다.
     - PC 메모리가 8GB 이상이면 기본 설정으로 충분하다.
   - **Mac**: Docker Desktop 설정 → Resources에서 메모리를 **4GB 이상**으로 둔다. 처음 빌드할 때 메모리를 많이 쓴다.
2. **소스를 받는다.** 아래 두 방법 중 하나를 쓴다.
   - Git이 있으면:
     ```bash
     git clone -b claude/wonderful-hypatia-l56bxc https://github.com/chsh2657-a11y/WellBuddyAI.git
     cd WellBuddyAI
     ```
   - Git이 없으면: GitHub 저장소에서 브랜치 `claude/wonderful-hypatia-l56bxc`를 고른다. **Code → Download ZIP**으로 내려받아 압축을 풀고, 그 폴더에서 터미널(PowerShell)을 연다.

## 2. 실행

```bash
docker compose up -d --build
```

- **처음 실행은 5~10분쯤 걸린다.** 이미지를 내려받고 앱을 빌드하기 때문이다. 다음부터는 몇 초면 뜬다.
- 상태는 `docker compose ps`로 확인한다.
  - `api`가 `healthy`이고 `web`이 `running`이면 준비된 것이다.
  - `setup`은 DB 준비를 마치면 `Exited (0)`으로 끝나는 것이 정상이다.

| 주소 | 내용 |
|---|---|
| http://localhost:3000 | **WellBuddy 웹(여기서 테스트한다)** |
| http://localhost:8025 | 메일함(초대 메일이 실제로 나가지 않고 여기에 쌓인다) |
| http://localhost:4000/api/docs | API 문서(개발자용) |

## 3. 로그인

- **데모 계정**: `demo@wellbuddy.local` / `demo1234!`
  - 빈 회사 "데모상사"(사업자번호 124-81-00998)다. 표준 계정과목만 들어 있다.
- 처음부터 해 보려면 [회원가입]으로 새 계정과 회사를 만든다.
  - 사업자번호는 검증번호가 맞아야 한다. 예: `124-81-00998`

## 4. 시험해 볼 것 (체크리스트)

각 항목은 "어디서 → 무엇을 → 기대 결과" 순서로 적었다. 해 본 항목에 ✔ 표시를 하면서 진행하면 좋다.

### P0 기반
- [ ] **가입·회사**: 회원가입 → 회사 만들기 → 대시보드가 열린다. 화면 위쪽의 회사 이름을 누르면 회사를 전환하거나 새 회사를 만들 수 있다.
- [ ] **사용자 초대**: 설정 → 사용자·권한 → 이메일과 역할(경리·직원 등)을 넣고 [초대 보내기]
  - http://localhost:8025 메일함에 초대 메일이 온다.
  - 메일의 링크를 다른 브라우저(또는 시크릿 창)에서 열어 가입하면 회사 구성원이 된다.
- [ ] **권한**: "직원" 역할로 들어가면 회계·증빙 메뉴가 보이지 않는다. 설정 → 사용자·권한에서 역할별 권한을 바꿀 수 있다.
- [ ] **메뉴 사용**: 설정 → 메뉴 사용에서 모듈을 끄면 왼쪽 메뉴에서 사라진다.
- [ ] **회사정보**: 설정 → 회사정보·사업장에서 "전표 승인 사용"을 켜면, 경리가 만든 전표는 승인요청을 거쳐야 전기된다.
- [ ] **감사로그**: 설정 → 감사로그에 누가 언제 무엇을 바꿨는지 남는다.

### P1 회계
- [ ] **기초정보**: 회계 → 계정과목·거래처·부서·프로젝트
  - 거래처를 등록할 때 사업자번호가 틀리면 막힌다.
  - 거래처 화면의 엑셀 일괄등록에서 **양식을 내려받아** 채운 뒤 올리면 한꺼번에 등록된다.
- [ ] **회계기간**: 회계 → 회계기간·마감
  - 기초잔액을 입력한다.
  - 월을 마감하면 그 달 전표를 입력·수정할 수 없다.
- [ ] **전표입력**: 회계 → 전표입력
  - 키보드로 입력한다(Enter로 다음 칸, Ctrl+Enter로 저장). 계정은 코드·이름·초성(예: ㅂㅌ → 보통예금)으로 찾는다.
  - 차변·대변이 맞지 않으면 저장되지 않는다.
  - 매입매출전표에서 공급가액을 넣으면 부가세와 분개가 자동으로 만들어진다.
- [ ] **입금·출금**: 회계 → 입금·출금에서 간편 입력한다.
- [ ] **전표조회**: 승인·전기·반려·역분개를 해 본다. 전기한 전표는 고칠 수 없고 역분개로만 취소된다.
- [ ] **장부·보고서**: 일계표·월계표, 계정별원장, 거래처원장, 현금출납장, 총계정원장, 합계잔액시산표(대차 일치), 재무제표, 채권·채무
  - 각 보고서에서 [엑셀]과 [인쇄]를 눌러 본다.
- [ ] **대시보드**: 현금·예금·미수금·미지급금 카드와 월별 매출·비용 그래프가 전표에 맞게 바뀐다.

### P1b 회계 확장
- [ ] **고정자산**: 회계 → 고정자산
  - 자산을 등록하고 월 감가상각을 실행하면 상각 전표가 생긴다.
  - 처분하면 처분손익 전표가 생긴다.
- [ ] **외화**: 회계 → 환율·외화평가
  - 환율을 넣고, 전표입력에서 "외화 입력"을 켜서 USD 전표를 만든다.
  - 기말 외화평가를 하면 외화환산손익 전표가 생긴다.
- [ ] **어음**: 회계 → 어음관리. 받을어음 수취 → 할인 또는 만기 결제, 지급어음 만기 결제
- [ ] **예산**: 회계 → 예산에서 부서별 예산을 넣는다 → 장부·보고서 → 예산 대비 실적에서 집행률과 초과를 확인한다.
- [ ] **자금**: 장부·보고서 → 일일자금일보, 자금계획(예정 입출금 → 일자별 예상 잔액)
- [ ] **부서·프로젝트별 손익**: 장부·보고서 → 부서·프로젝트별 손익

### P2 증빙·자동분개
가장 빨리 체험하는 방법은 **모의 데이터**다. 실제 은행·카드 계약 없이 그럴듯한 거래를 만들어 준다.

- [ ] **계좌·카드 등록**: 증빙·자동분개 → 계좌·카드에서 은행 계좌와 법인카드를 하나씩 등록한다. 번호는 끝 4자리만 보인다.
- [ ] **연동 켜기**: 설정 → 연동관리 → 은행 입출금·법인카드·홈택스 증빙 카드에서
  1. 연동 방식을 "모의 데이터"로 고른다.
  2. 사용 스위치를 켜고 [저장]한다.
- [ ] **자동 수집**: 증빙·자동분개 → 자동 수집 → 채널별 [지금 수집]을 누른다(최근 30일).
  - 다시 누르면 "새로 0건, 중복 N건"이 나온다. 같은 거래를 두 번 가져오지 않는다.
- [ ] **자동분개**: 증빙·자동분개 → 자동분개 검토함 → [자동분개 실행]
  - 거래마다 추천 계정, 근거, 신뢰도, 전표 미리보기가 나온다.
  - 계정을 고친 뒤 [승인]하면 전표가 만들어지고, 고친 내용을 학습한다.
- [ ] **분개 규칙**: 증빙·자동분개 → 분개 규칙
  - 예: 키워드 "임대료" → 819 지급임차료
  - 규칙을 만들고 다시 실행하면 신뢰도 100%가 된다.
  - 검토함의 "신뢰도 높은 거래는 자동 전기"를 켜면 검토 없이 전표가 된다.
  - 같은 거래를 3번 이상 같은 계정으로 승인하면 "추천 규칙"이 나타난다.
- [ ] **잔액 대사**: 증빙·자동분개 → 잔액 대사에서 통장 잔액과 장부 잔액을 비교한다. 미반영 거래가 따로 표시된다.
- [ ] **증빙센터**: 모든 증빙의 처리 상태(미처리·검토 필요·전표 연결)를 한 화면에서 본다.
- [ ] **세금계산서 발행(모의)**
  1. 설정 → 연동관리 → 전자세금계산서 발행을 "모의 데이터"로 켠다.
  2. 증빙·자동분개 → 세금계산서 발행에서 발행한다.
  - 승인번호가 나오고 매출 세금계산서로 등록된다. 상태 확인과 발행 취소도 해 본다.

| `20261015_스타벅스 역삼점_5500_113-81-55305.png` | 영수증 탭 | 카드 승인과 짝지어지는 영수증 |
| `20261016_카카오T 택시_15300_120-86-44100.png` | 영수증 탭 | 사업자번호가 틀려 "검토 필요"가 되는 영수증 |

순서:
1. 계좌·카드 탭에서 **KB국민은행 계좌**와 **신한카드**를 등록한다.
2. 파일 올리기 탭에서 자료 종류를 고르고 파일을 올린다 → [미리보기] → [N건 등록]
   - 같은 파일을 다시 올리면 중복으로 알려 준다.
3. **영수증**: 설정 → 연동관리 → 영수증 인식(OCR)을 "모의 데이터"로 켠다. 그다음 영수증 탭에 PNG 두 장을 끌어다 놓는다.
   - 모의 OCR은 파일 이름 `날짜_가맹점_금액_사업자번호`를 읽는다. 내 영수증 사진도 이렇게 이름을 바꾸면 똑같이 시험할 수 있다.
4. 자동분개 검토함에서 [자동분개 실행]을 누른다. 기대 결과:
   - 매칭 2건: 카드 승인·취소가 서로 상쇄되고, 스타벅스 영수증이 카드 승인과 짝지어진다.
   - 나머지는 검토 대기다.
5. 세금계산서 3건을 먼저 [승인]한 뒤 다시 실행하면 외상 반제가 추천된다.
   - 한빛상사 입금 1,100,000원 → 외상매출금 반제
   - 대한물산 송금 550,000원 → 외상매입금 반제

> 내 회사 사업자번호가 124-81-00998이 아니면, 세금계산서 파일을 올릴 때 "매출·매입"을 직접 골라야 한다(또는 파일 속 번호를 내 번호로 바꾼다).
> 실제 은행·카드사·홈택스에서 내려받은 엑셀·CSV도 올릴 수 있다. 국민·신한·우리·하나·농협·기업은행 양식은 자동으로 인식하고, 처음 보는 양식은 열을 직접 지정한다.

### P3 영업·구매·재고 (개발 중 — 되는 것부터)
- [ ] **기초정보**: 영업·구매·재고 → 품목·창고·거래처별 단가
  - 품목을 추가한다. 상품·제품·원재료·서비스, 규격·단위·바코드·판매/구매단가·적정재고를 넣는다.
  - 엑셀 양식으로 한꺼번에 올릴 수 있다.
  - 창고는 처음에 "기본창고"가 있다.
  - 거래처를 고르면 품목마다 그 거래처에만 쓰는 단가를 정할 수 있다.
- [ ] **구매**: 구매 탭 → 새 발주서 → [입고 만들기]로 일부만 입고 → [구매 만들기]로 단가를 고쳐 확정
  - 입고하면 재고와 입고 전표(상품/외상매입금)가 생긴다.
  - 구매로 넘기면 입고 전표가 역분개되고 매입 전표(부가세 포함)로 바뀐다.
  - 발주의 남은 수량, 취소하면 되돌아가는지, 구매반품도 확인한다.
- [ ] **판매**: 판매 탭 → 새 견적서 → [주문서 만들기] → [출고 만들기] → [판매 만들기] → [거래명세서 인쇄]
  - 출고하면 이동평균 원가로 매출원가 전표(매출원가/상품)가 생긴다.
  - 판매하면 매출 전표(외상매출금/상품매출·부가세예수금)가 생긴다.
  - 재고보다 많이 출고하면 막힌다. 판매반품도 해 본다.
- [ ] **재고**: 재고 탭에서 현재고(창고별 수량·평균단가·재고금액)를 본다. 품목을 누르면 재고수불부가 나온다.
  - 장부·보고서 → 계정별원장에서 146 상품 잔액이 재고금액 합계와 같은지 확인한다.
  - 지난 날짜로 입고를 넣으면(소급) 이후 출고의 매출원가가 자동으로 다시 계산된다.

## 5. 아직 안 되는 것

- **생산(P4) 이후 메뉴는 "준비 중"이다.** 생산, 전자결재, 인사·그룹웨어, 근태, 급여, 부가세·결산이 여기에 해당한다.
- **영업·구매·재고 중 아직 안 되는 것**: 판매 세금계산서 발행 연계, 창고 간 이동, 재고 실사·조정, LOT·시리얼, 바코드 스캔, 적정재고 알림, 영업 이력, 인쇄양식 설정
- **실제 외부 연동은 계약 키가 있어야 한다.** CODEF(은행·카드·홈택스), 팝빌(홈택스·세금계산서 발행), Claude AI(자동분개·영수증 인식), Upstage·CLOVA OCR, 공공데이터포털이 그렇다.
  - 키 없이는 "모의 데이터"로 테스트한다.
  - 키가 있으면 설정 → 연동관리에서 입력한 뒤 [연결 테스트]로 확인할 수 있다.
- 이 실행 환경은 **테스트 전용**이다. 비밀키가 공개된 기본값이므로 실제 회사 자료를 넣거나 인터넷에 공개하지 않는다.

## 6. 중지·초기화·업데이트

| 하려는 일 | 명령 |
|---|---|
| 멈추기(데이터 유지) | `docker compose down` |
| 다시 켜기 | `docker compose up -d` |
| **데이터까지 모두 지우고 처음부터** | `docker compose down -v` 다음에 `docker compose up -d --build` |
| 새 버전 받기 | `git pull` 다음에 `docker compose up -d --build` |
| 로그 보기 | `docker compose logs -f api` (워커는 `worker`, 웹은 `web`) |

## 7. 문제 해결

- **`'docker' 용어가 … 인식되지 않습니다`**(Windows)가 나오면, Docker Desktop이 설치되지 않았거나 설치 전에 연 PowerShell 창을 쓰고 있는 것이다. 위의 "1. 준비"대로 설치하고 새 창에서 다시 실행한다.
- **포트가 이미 쓰이고 있다**는 오류가 나면, 다른 포트로 띄운다. 예: `WEB_PORT=3100 API_PORT=4100 MAIL_PORT=8125 docker compose up -d`
  - 이때 주소는 http://localhost:3100 이 된다.
  - Windows PowerShell에서는 `$env:WEB_PORT=3100; docker compose up -d`처럼 쓴다.
- **첫 빌드가 중간에 실패하면** 대개 네트워크가 끊겼거나 메모리가 부족한 것이다. 메모리를 늘리고 `docker compose up -d --build`를 다시 실행한다.
- **`setup`이 `Exited (1)`로 끝나면** `docker compose logs setup`으로 원인을 보고, `docker compose down -v` 후 다시 실행한다.
- **화면이 안 뜨면** `docker compose ps`로 `api`가 `healthy`인지 확인한다. 처음 뜰 때 30초쯤 걸릴 수 있다.
- **Apple Silicon(M1~M4) Mac**도 그대로 동작한다.
